# IceFactory — техническая спецификация реализации

Документ фиксирует вариант практической реализации ТЗ для веб-системы автоматизации мороженого завода.

## 1. Предлагаемый стек

- **Backend**: Node.js + NestJS (или Express) с REST API.
- **Frontend**: React (или любой SPA-фреймворк).
- **БД**: PostgreSQL 14+.
- **Аутентификация**: JWT + refresh-токены.
- **Хеширование паролей**: Argon2id (предпочтительно) либо bcrypt.

## 2. Модули системы

1. **Auth & Users**
   - логин/пароль;
   - роли: ADMIN, WAREHOUSE, TECHNOLOGIST, QC, SALES;
   - блокировка пользователя.

2. **Справочники**
   - единицы измерения;
   - сырье;
   - поставщики;
   - готовая продукция;
   - клиенты.

3. **Склад сырья**
   - приход;
   - списание;
   - журнал движений;
   - контроль минимального остатка.

4. **Рецептуры**
   - версия рецептуры;
   - состав ингредиентов и норм;
   - расчет планового расхода на партию.

5. **Партии производства**
   - создание партии;
   - план-факт расхода сырья;
   - статусы партии;
   - выпуск продукции.

6. **ОТК**
   - контроль партии;
   - решение PASS/FAIL;
   - блокировка партии при FAIL.

7. **Заказы и отгрузки**
   - заказ клиента;
   - отгрузка;
   - проверка остатков;
   - списание со склада готовой продукции.

8. **Отчетность**
   - остатки;
   - движения;
   - выпуск;
   - расход;
   - отгрузки.

## 3. Карта статусов

### 3.1 Статусы партии

- `PLANNED` → `IN_PROGRESS` → `READY_FOR_QC`
- `READY_FOR_QC` → `APPROVED` или `BLOCKED`
- `APPROVED` → `COMPLETED`

### 3.2 Статусы заказа

- `NEW` → `CONFIRMED` → `SHIPPED`
- `NEW`/`CONFIRMED` → `CANCELLED`

## 4. Бизнес-правила целостности

- запрещены отрицательные остатки (реализовано триггерами в БД);
- нельзя создать партию с нулевым/отрицательным объемом;
- нельзя отгрузить больше, чем есть на складе готовой продукции;
- при результате ОТК `FAIL` партия автоматически получает статус `BLOCKED`;
- критические операции сохраняют автора и дату/время.

## 5. Транзакционные сценарии

1. **Списание сырья на партию**
   - запись в `batch_material_consumption`;
   - запись в `raw_material_movements` (OUT);
   - обновление статуса партии (при необходимости).

2. **Выпуск готовой продукции**
   - обновление `production_batches.produced_quantity`;
   - запись в `finished_goods_movements` (IN).

3. **Отгрузка по заказу**
   - создание `shipments` + `shipment_items`;
   - запись в `finished_goods_movements` (OUT);
   - перевод заказа в `SHIPPED` при полном выполнении.

Все шаги выполняются в одной транзакции.

## 6. Отчеты (SQL-уровень)

- остатки сырья: `v_raw_material_stock`;
- остатки готовой продукции: `v_finished_goods_stock`;
- движения за период: фильтрация по `movement_date`;
- выпуск по партиям: `production_batches` + `produced_quantity`;
- расход по партиям: `batch_material_consumption`;
- продажи по клиентам: `customer_orders` + `shipments`.

## 7. Резервное копирование PostgreSQL

Рекомендуемая процедура:

- ежедневный полный дамп:
  ```bash
  pg_dump -Fc -h <host> -U <user> -d icefactory > backup_$(date +%F).dump
  ```
- хранение копий минимум 14 дней;
- еженедельная проверка восстановления:
  ```bash
  pg_restore --clean --if-exists -h <host> -U <user> -d icefactory_restore backup_YYYY-MM-DD.dump
  ```

## 8. Минимальный API-контур

- `POST /auth/login`
- `GET/POST/PATCH /users`
- `GET/POST/PATCH /materials`
- `POST /materials/movements/in`
- `POST /materials/movements/out`
- `GET/POST /recipes`
- `GET/POST /batches`
- `POST /batches/{id}/consume`
- `POST /batches/{id}/release`
- `POST /qc/checks`
- `GET/POST /orders`
- `POST /orders/{id}/ship`
- `GET /reports/*`
